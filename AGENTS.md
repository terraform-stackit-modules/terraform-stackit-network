# Agent Guidelines

This file provides context and instructions for AI coding agents (Copilot, Cursor, Codex, etc.) working on this repository.

## Project context

This is a Terraform module for [STACKIT](https://www.stackit.de/en/), the cloud platform by Schwarz Group.
It is part of the [terraform-stackit-modules](https://github.com/terraform-stackit-modules) organization, which aims to provide community-maintained, production-grade Terraform modules for STACKIT.

This module creates a **STACKIT network** with optional security group and rules, designed for use with STACKIT virtual machines and managed databases.

## Resources managed

| Resource | Condition |
|----------|-----------|
| `stackit_network` | always created |
| `stackit_security_group` | only when `create_security_group = true` |
| `stackit_security_group_rule` | only when `create_security_group = true` and `security_group_rules` is non-empty |

## Key variables

| Variable | Type | Required | Description |
|----------|------|----------|-------------|
| `project_id` | `string` | yes | STACKIT project ID |
| `name` | `string` | yes | Network name, also used to derive the security group name (`<name>-sg`) |
| `create_security_group` | `bool` | no (default `false`) | Toggle security group creation |
| `security_group_rules` | `list(object)` | no | Rules with `direction`, `ether_type`, `ip_range`, `remote_security_group_id`, `protocol` (`name` or `number`), `port_range`, `icmp_parameters` |

## Outputs

| Output | Description |
|--------|-------------|
| `network_id` | ID of the created network |
| `network_name` | Name of the created network |
| `ipv4_prefix` | IPv4 CIDR assigned to the network |
| `ipv6_prefix` | IPv6 CIDR assigned to the network |
| `security_group_id` | ID of the security group (`null` if not created) |
| `security_group_name` | Name of the security group (`null` if not created) |

## Coding conventions

- Terraform version: `>= 1.3`
- Provider: `stackitcloud/stackit >= 0.113.0` — do NOT use `hashicorp/stackit`
- All variables must have `description` and `type`
- All outputs must have `description`
- Naming convention: `snake_case` for all resources, variables, and outputs
- No hardcoded values — use variables
- `project_id` is always a required variable of type `string`
- Use `count` only for on/off toggles (`create_security_group`), use `for_each` for resource iteration
- `protocol`, `port_range`, and `icmp_parameters` on `stackit_security_group_rule` are `nested_type/single` attributes — use `= {}` syntax, NOT `dynamic {}` blocks

## CI/CD

- `pre-commit` runs `terraform_fmt`, `terraform_validate`, `terraform_docs`, `terraform_tflint` on every PR
- `README.md` is auto-generated by `terraform-docs` from `.header.md` — never edit it directly
- Releases are managed by `semantic-release` using conventional commits — requires `SEMANTIC_RELEASE_TOKEN` secret
- Terratest runs real infrastructure tests against STACKIT — requires `STACKIT_SERVICE_ACCOUNT_KEY` and `STACKIT_PROJECT_ID` secrets

## Commit convention

Follow [Conventional Commits](https://www.conventionalcommits.org/):

- `feat:` new feature → minor version bump
- `fix:` bug fix → patch version bump
- `improvement:` enhancement → patch version bump
- `docs:` documentation → no bump
- `refactor:` refactoring → no bump
- `test:` tests → no bump
- `ci:` CI/CD changes → no bump
- `chore:` maintenance → no bump (skipped in changelog)

## What to avoid

- Do not edit `README.md` directly
- Do not use `for_each` or `count` where a simple attribute assignment suffices
- Do not pin provider versions to an exact version in modules — use `>=`
- Do not commit `.terraform/`, `*.tfstate`, or `*.tfstate.backup`
- Do not add `dynamic` blocks for `nested_type/single` attributes in the STACKIT provider
